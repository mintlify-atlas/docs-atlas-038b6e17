The Events API lets you send structured telemetry from your application and retrieve aggregated metrics — useful for error tracking, audit logs, and operational visibility. Every event is scoped to the project associated with your API key, so data from different projects stays isolated.

<Note>
  All event endpoints require a valid API key passed as a Bearer token: `Authorization: Bearer veyra_YOUR_API_KEY`. You can generate API keys from the Veyra dashboard or via the [Auth API](/api/auth).
</Note>

---

## POST /v1/events

Logs a structured event from your application. Events are stored and associated with the authenticated project, and are immediately reflected in metrics.

**Endpoint:** `POST https://api.strixhost.xyz/v1/events`

**Authentication:** `Authorization: Bearer veyra_API_KEY`

### Request body

<ParamField body="level" type="string" required>
  Severity level of the event. Must be one of: `"info"`, `"warn"`, `"error"`, `"debug"`.
</ParamField>

<ParamField body="message" type="string" required>
  Human-readable description of the event (e.g. `"Database connection failed"`).
</ParamField>

<ParamField body="source" type="string" required>
  The originating service or component that generated this event (e.g. `"Payment-Service"`, `"Auth-Worker"`). Used for grouping in metrics.
</ParamField>

<ParamField body="environment" type="string" required>
  The deployment environment the event originated from (e.g. `"production"`, `"staging"`). Helps distinguish events across deploy targets.
</ParamField>

### Request examples

<CodeGroup>

```bash bash
curl -X POST https://api.strixhost.xyz/v1/events \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer veyra_your_api_key_here" \
  -d '{"level": "error", "message": "Database connection failed", "source": "Payment-Service", "environment": "production"}'
```

```javascript javascript
const res = await fetch('https://api.strixhost.xyz/v1/events', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer veyra_your_api_key_here'
  },
  body: JSON.stringify({
    level: 'error',
    message: 'Database connection failed',
    source: 'Payment-Service',
    environment: 'production'
  })
});
```

</CodeGroup>

### Response

**200 — Event logged successfully**

<ResponseField name="id" type="string">
  Unique identifier for the created event record.
</ResponseField>

<ResponseField name="level" type="string">
  The severity level as provided in the request (`"info"`, `"warn"`, `"error"`, or `"debug"`).
</ResponseField>

<ResponseField name="message" type="string">
  The human-readable event description as provided in the request.
</ResponseField>

<ResponseField name="source" type="string">
  The originating service or component as provided in the request.
</ResponseField>

<ResponseField name="environment" type="string">
  The deployment environment as provided in the request.
</ResponseField>

<ResponseField name="timestamp" type="string">
  ISO 8601 timestamp of when the event was received and stored by Veyra.
</ResponseField>

<ResponseField name="projectId" type="string">
  The project ID the event was logged against, derived from the API key used to authenticate.
</ResponseField>

**400 — Missing required fields**

Returned when one or more of `level`, `message`, `source`, or `environment` are absent from the request body. The response body will include a `message` field describing which fields are missing.

**401 — Invalid API key**

Returned when the `Authorization` header is missing, malformed, or the API key is not recognised. Ensure your key starts with `veyra_` and has not been revoked.

<Tip>
  Use consistent `source` values across your services — for example, always use `"Payment-Service"` rather than mixing `"payment"`, `"payments-svc"`, and `"PaymentWorker"`. Consistent naming makes the `bySource` breakdown in metrics immediately useful for spotting which service is generating the most noise.
</Tip>

## GET /v1/events/metrics

Returns aggregated event statistics for the project associated with the authenticated API key. Metrics are computed across all events logged for the project.

**Endpoint:** `GET https://api.strixhost.xyz/v1/events/metrics`

**Authentication:** `Authorization: Bearer veyra_API_KEY`

### Request examples

<CodeGroup>

```bash bash
curl https://api.strixhost.xyz/v1/events/metrics \
  -H "Authorization: Bearer veyra_your_api_key_here"
```

```javascript javascript
const res = await fetch('https://api.strixhost.xyz/v1/events/metrics', {
  headers: { 'Authorization': 'Bearer veyra_your_api_key_here' }
});
const metrics = await res.json();
console.log(metrics);
```

</CodeGroup>

### Response

**200 — Metrics returned successfully**

<ResponseField name="total" type="number">
  Total number of events logged for this project across all levels and sources.
</ResponseField>

<ResponseField name="byLevel" type="object">
  An object mapping each severity level to its event count. Keys are `"info"`, `"warn"`, `"error"`, and `"debug"`. Example: `{ "error": 42, "warn": 17, "info": 305, "debug": 88 }`.
</ResponseField>

<ResponseField name="bySource" type="object">
  An object mapping each unique `source` value to its event count. Example: `{ "Payment-Service": 120, "Auth-Worker": 332 }`.
</ResponseField>

<ResponseField name="timeRange" type="object">
  An object describing the time window covered by the returned metrics, with `from` and `to` fields as ISO 8601 timestamps.
</ResponseField>

**401 — Invalid API key**

Returned when the `Authorization` header is missing, malformed, or the API key is not recognised.
