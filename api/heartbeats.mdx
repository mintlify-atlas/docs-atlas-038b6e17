The Heartbeats API implements a dead-man's-switch pattern — your service pings Veyra on a schedule, and silence past the configured `heartbeatInterval` signals a problem. When Veyra stops receiving pings within the expected window, it automatically fires a downtime alert for your project. This approach catches crashes, hangs, and deployment failures that might not otherwise surface as explicit errors.

<Note>
  Heartbeat endpoints use API key authentication (`Authorization: Bearer veyra_YOUR_API_KEY`). The `projectId` path parameter is the ID returned when you created the project via [POST /v1/projects](/api/projects). You can also find it in the Veyra dashboard.
</Note>

---

## POST /v1/heartbeats/:projectId

Records an uptime heartbeat ping for the given project. Each successful request resets the downtime countdown for that project — as long as pings arrive within the project's `heartbeatInterval`, the project is considered healthy.

**Endpoint:** `POST https://api.strixhost.xyz/v1/heartbeats/:projectId`

**Authentication:** `Authorization: Bearer veyra_API_KEY`

### Path parameters

<ParamField path="projectId" type="string" required>
  The unique project ID to record a heartbeat for. Obtained from the response of `POST /v1/projects` or from the Veyra dashboard.
</ParamField>

### Request body

No request body is required. A bare POST to the endpoint with a valid API key and project ID is sufficient.

### Request examples

<CodeGroup>

```bash bash
curl -X POST https://api.strixhost.xyz/v1/heartbeats/YOUR_PROJECT_ID \
  -H "Authorization: Bearer veyra_your_api_key_here"
```

```javascript javascript
await fetch(`https://api.strixhost.xyz/v1/heartbeats/${PROJECT_ID}`, {
  method: 'POST',
  headers: { 'Authorization': `Bearer ${API_KEY}` }
});
```

```python python
import requests

requests.post(
    f'https://api.strixhost.xyz/v1/heartbeats/{project_id}',
    headers={'Authorization': f'Bearer {api_key}'}
)
```

</CodeGroup>

### Response

**200 — Heartbeat recorded successfully**

<ResponseField name="projectId" type="string">
  The project ID the heartbeat was recorded against, echoed back from the URL path.
</ResponseField>

<ResponseField name="timestamp" type="string">
  ISO 8601 timestamp of when Veyra received and recorded the ping.
</ResponseField>

<ResponseField name="status" type="string">
  Always `"ok"` on a successful ping. Confirms the heartbeat was accepted and the countdown has been reset.
</ResponseField>

**401 — Invalid API key**

Returned when the `Authorization` header is missing, malformed, or the API key is not recognised. Check that your key starts with `veyra_` and has not been revoked.

**404 — Project not found**

Returned when the `projectId` in the URL does not correspond to any project accessible by the authenticated API key. Verify the project ID in your dashboard or re-check the value returned by `POST /v1/projects`.

## Scheduling heartbeats

Your heartbeat pings must arrive at least as often as the project's configured `heartbeatInterval`. If you set a 60-second interval on the project, your service must ping at least every 60 seconds — a gap longer than that will trigger a downtime alert.

### JavaScript — `setInterval`

Use `setInterval` to ping on a fixed cadence matching your project's `heartbeatInterval`:

```javascript
const PROJECT_ID = 'your_project_id';
const API_KEY = 'veyra_your_api_key_here';
const INTERVAL_MS = 30_000; // match your project's heartbeatInterval

setInterval(async () => {
  try {
    await fetch(`https://api.strixhost.xyz/v1/heartbeats/${PROJECT_ID}`, {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${API_KEY}` }
    });
  } catch (err) {
    // Log the error but do NOT rethrow — a failed ping must not crash the service
    console.error('Heartbeat ping failed:', err);
  }
}, INTERVAL_MS);
```

### Bash — cron job

For long-running scripts or server-side jobs, use a cron entry to fire the ping on a schedule:

```bash
# Run a heartbeat every minute — edit the schedule to match your heartbeatInterval
* * * * * curl -s -X POST https://api.strixhost.xyz/v1/heartbeats/YOUR_PROJECT_ID \
  -H "Authorization: Bearer veyra_your_api_key_here" > /dev/null 2>&1
```

Adjust the cron schedule (`* * * * *` runs every minute) to align with your project's configured interval.

<Warning>
  Always wrap heartbeat calls in a `try/catch` (or equivalent error handling in your language). A transient network error or a non-2xx response from Veyra should be **logged and swallowed** — it must never propagate as an uncaught exception and crash your service. The purpose of heartbeats is to detect when your service goes down; letting a failed ping bring down your service defeats the point entirely.
</Warning>
