title: "Get Started with Veyra in 5 Minutes"
sidebarTitle: "Quickstart"

---

By the end of this guide, you'll have a Veyra account, a configured project, a working API key, and your first event and heartbeat recorded — all in under five minutes. No SDK required; every step uses plain HTTP requests you can run from your terminal.

<Steps>

  <Step title="Register an account">
    Create your Veyra account by sending your email and password to the registration endpoint. No email verification is required to get started.

    ```bash
    curl -X POST https://api.strixhost.xyz/v1/auth/register \
      -H "Content-Type: application/json" \
      -d '{
        "email": "dev@example.com",
        "password": "supersecure123"
      }'
    ```

    A successful response will confirm your account has been created. You're ready to log in.
  </Step>

  <Step title="Log in and save your JWT token">
    Authenticate with the same credentials to receive a JWT token. This token is your management credential — you'll need it to create projects and generate API keys.

    ```bash
    curl -X POST https://api.strixhost.xyz/v1/auth/login \
      -H "Content-Type: application/json" \
      -d '{
        "email": "dev@example.com",
        "password": "supersecure123"
      }'
    ```

    The response will include a `token` field. Copy the value and store it in your shell session:

    ```bash
    export JWT_TOKEN="your_jwt_token_here"
    ```

    <Note>
      JWT tokens are short-lived management credentials. Do not embed them in your application code or services — they are only meant for administrative operations like the ones in the next two steps.
    </Note>
  </Step>

  <Step title="Create a project">
    Projects are the top-level containers for your events, heartbeats, and incidents. Create one by providing a name, an environment label, and a heartbeat interval in milliseconds.

    ```bash
    curl -X POST https://api.strixhost.xyz/v1/projects \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer YOUR_JWT_TOKEN" \
      -d '{
        "name": "My Backend",
        "environment": "production",
        "heartbeatInterval": 60000
      }'
    ```

    The response will include an `id` field — this is your **project ID**. Save it; you'll use it in the next step and when sending heartbeats.

    ```bash
    export PROJECT_ID="your_project_id_here"
    ```
  </Step>

  <Step title="Generate an API key">
    API keys are scoped to a single project and used by your services to send telemetry. Generate one now for the project you just created.

    ```bash
    curl -X POST https://api.strixhost.xyz/v1/projects/YOUR_PROJECT_ID/keys \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer YOUR_JWT_TOKEN" \
      -d '{
        "name": "Production API Key"
      }'
    ```

    The response will include the full API key, prefixed with `veyra_`. Save it immediately:

    ```bash
    export VEYRA_API_KEY="veyra_your_api_key_here"
    ```

    <Warning>
      **Your API key is only shown once.** Veyra does not store the plaintext key after generation — if you lose it, you'll need to generate a new one. Save it to a secure location (such as a password manager or secrets manager) before closing this terminal session.
    </Warning>
  </Step>

  <Step title="Send your first event">
    Events are structured log entries — errors, warnings, or informational messages — sent from your services using your API key. Send a test event now:

    ```bash
    curl -X POST https://api.strixhost.xyz/v1/events \
      -H "Content-Type: application/json" \
      -H "Authorization: Bearer veyra_YOUR_API_KEY" \
      -d '{
        "level": "error",
        "message": "Database connection failed",
        "source": "Payment-Service",
        "environment": "production"
      }'
    ```

    A successful response confirms the event was ingested. You should see it appear in your project's event feed.
  </Step>

  <Step title="Send a heartbeat ping">
    Heartbeats let Veyra know that a service, cron job, or bot is still alive. Ping your project's heartbeat endpoint to register a successful check-in:

    ```bash
    curl -X POST https://api.strixhost.xyz/v1/heartbeats/YOUR_PROJECT_ID \
      -H "Authorization: Bearer veyra_YOUR_API_KEY"
    ```

    If Veyra stops receiving pings within the `heartbeatInterval` you configured (60 seconds in this example), it will mark the service as down and trigger an alert.

    <Tip>
      In production, schedule this request to run at an interval shorter than your configured `heartbeatInterval` — for example, every 30 seconds for a 60-second interval — to avoid false-positive downtime alerts due to network jitter.
    </Tip>
  </Step>

</Steps>

You've registered an account, created a project, generated an API key, and sent both an event and a heartbeat. Your Veyra integration is live.
